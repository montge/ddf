ARTIFACT NAME CHANGES (VERSION 30.0+)
================================================================================

CRITICAL CHANGE - Package Reorganization in GeoTools 30.0:
----------------------------------------------------------

1. gt-opengis → gt-api
   OLD: org.geotools:gt-opengis:24.6
   NEW: org.geotools:gt-api:33.3

   Reason: OGC requested GeoTools stop using org.opengis package namespace

2. gt-jts-wrapper → REMOVED (no replacement)
   Status: Removed after version 24.7

   Reason: ISO Geometry interfaces were removed from GeoTools 30.0. The project
   now uses JTS (Java Topology Suite) directly throughout. The gt-jts-wrapper
   was a bridge to ISO 19107 geometry interfaces that are no longer supported.

   Migration: Remove dependency and use JTS geometries directly

3. XSD Modules - GroupId Change:
   OLD: org.geotools:gt-xsd-core
   NEW: org.geotools.xsd:gt-xsd-core

   Note: These have been under org.geotools.xsd groupId since at least
   version 27.x. The artifactIds remain the same.

================================================================================
API BREAKING CHANGES: 24.6 → 33.3
================================================================================

1. PACKAGE RENAME (Version 30.0+)
   ------------------------------
   ALL imports must be updated:

   org.opengis.*           →  org.geotools.api.*

   Examples:
   - org.opengis.filter.*         → org.geotools.api.filter.*
   - org.opengis.feature.*        → org.geotools.api.feature.*
   - org.opengis.referencing.*    → org.geotools.api.referencing.*
   - org.opengis.geometry.*       → org.geotools.api.geometry.*

   Migration Script: GeoTools provides an Ant script (remove-opengis.xml)
   to automate this conversion.

2. CORE DATA API MOVED (Version 30.0+)
   ------------------------------------
   org.geotools.data.*     →  org.geotools.api.data.*

   Main data access interfaces moved to API package.

3. GEOMETRY CLASSES RENAMED (Version 30.0+)
   -----------------------------------------
   org.opengis.geometry.Envelope          → org.geotools.api.geometry.Bounds
   org.geotools.geometry.GeneralEnvelope  → org.geotools.geometry.GeneralBounds
   org.opengis.geometry.DirectPosition    → org.geotools.api.geometry.Position
   org.geotools.geometry.GeneralDirectPosition → org.geotools.geometry.GeneralPosition

4. ISO GEOMETRY REMOVAL (Version 30.0+)
   -------------------------------------
   - All org.opengis.geometry interfaces for Point, Curve, Surface removed
   - gt-jts-wrapper module removed (no longer needed)
   - Direct use of JTS (org.locationtech.jts.geom.*) throughout
   - No wrapper needed - use JTS Geometry classes directly

5. JAI → ImageN MIGRATION (Version 34.0+)
   ---------------------------------------
   Only affects version 34.0+. If staying on 33.3, this does not apply.

   javax.media.jai.*       →  org.eclipse.imagen.*

   ImageMosaicFormat properties:
   - USE_JAI_IMAGEREAD     → USE_IMAGEN_IMAGEREAD

6. JAVA VERSION REQUIREMENTS
   --------------------------
   - GeoTools 24.6:  Java 8+
   - GeoTools 30.x:  Java 11+
   - GeoTools 31.x:  Java 11+
   - GeoTools 32.x:  Java 11+
   - GeoTools 33.x:  Java 11+
   - GeoTools 34.x:  Java 17+

   DDF Status: Currently using Java 17 (maven.compiler.source=17)
              → Compatible with ALL versions

CONCLUSION
================================================================================

The upgrade from GeoTools 24.6 to a modern version (31.6, 33.3, or 34.0) is
FEASIBLE but requires significant code changes due to the org.opengis →
org.geotools.api package migration in version 30.0.

RECOMMENDED VERSION: 33.3
- Latest stable
- Java 11 compatible (DDF uses 17)
- Actively maintained
- Production-tested in GeoServer ecosystem
- Avoids ImageN migration complexity

The main upgrade effort involves:
1. Dependency changes (gt-opengis → gt-api, remove gt-jts-wrapper)
2. Package rename across entire codebase (org.opengis → org.geotools.api)
3. Geometry class renames (Envelope → Bounds, etc.)
4. Testing all geospatial functionality

Estimated effort: Medium (2-3 days development + 1-2 days testing)
Risk level: Medium (breaking API changes, but well-documented migration path)

The GeoTools project provides migration tools and comprehensive documentation
to assist with this upgrade.
